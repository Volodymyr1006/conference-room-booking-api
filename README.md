# Conference Rooms Booking API

REST API для управління конференц-залами, бронюваннями та розрахунку вартості оренди.
Клієнти шукають вільні зали, бронюють їх і одразу бачать вартість. Адміністратор керує залами й отримує звіти для бізнесу.

**Стек:** Node.js 22+ · Express 5 · SQLite (better-sqlite3) · Zod · Swagger (OpenAPI 3) · node:test + Supertest · Pino · Docker

> Бізнес-завдання та обґрунтування технічних рішень описано в [docs/PROJECT.md](docs/PROJECT.md).

## Швидкий старт

Потрібен лише [Node.js](https://nodejs.org) версії 22 або новішої. Базу даних окремо встановлювати не треба: SQLite зберігається у звичайному файлі.

```bash
npm install        # встановити залежності
npm run setup      # створити .env з випадковими API-ключами (ключі буде виведено в консоль)
npm run dev        # запустити сервер з автоперезапуском при зміні коду
```

- API: `http://localhost:3000/api/v1`
- **Swagger UI:** `http://localhost:3000/api-docs` (натисніть **Authorize** і вставте ключ з `.env`)
- Перевірка стану: `http://localhost:3000/health`

Під час першого запуску автоматично створюються таблиці й початкові дані з ТЗ: **Зал A, Зал B, Зал C** з послугами «Проєктор», «Wi-Fi», «Звук».

### Команди

| Команда | Що робить |
|---|---|
| `npm run setup` | Створює `.env` з новими API-ключами |
| `npm run dev` | Запуск для розробки (перезапуск при змінах) |
| `npm start` | Запуск у звичайному режимі |
| `npm test` | Запуск усіх автотестів |

### Запуск у Docker (необов'язково)

```bash
npm run setup
docker compose up --build
```

База зберігається в Docker volume `booking-data` і не зникає при перезапуску контейнера.

## Автентифікація та ролі

Кожен запит до `/api/v1` має містити заголовок `X-API-Key`.

| Роль | Ключ у `.env` | Що дозволено |
|---|---|---|
| **admin** | `ADMIN_API_KEY` | усе: створення, редагування й видалення залів, список усіх бронювань, звіти |
| **client** | `CLIENT_API_KEY` | перегляд і пошук залів, розрахунок вартості, бронювання, перегляд і скасування бронювання за id |

## API

Базова адреса: `/api/v1`. Дати у форматі `ДД.ММ.РРРР`, час `ГГ:ХХ`, суми в гривнях.

### Зали

| Метод | Шлях | Роль | Опис |
|---|---|---|---|
| `POST` | `/rooms` | admin | **Додати зал** → 201 + унікальний `id` |
| `PATCH` | `/rooms/{id}` | admin | **Редагувати зал** (лише передані поля) |
| `DELETE` | `/rooms/{id}` | admin | **Видалити зал** |
| `GET` | `/rooms/available` | client | **Пошук доступних залів** |
| `GET` | `/rooms` | client | Список залів |
| `GET` | `/rooms/{id}` | client | Інформація про зал |
| `POST` | `/rooms/{id}/services` | admin | Додати послугу до залу |
| `DELETE` | `/rooms/{id}/services/{serviceId}` | admin | Видалити послугу |

### Бронювання

| Метод | Шлях | Роль | Опис |
|---|---|---|---|
| `POST` | `/bookings` | client | **Забронювати зал** → підтвердження з розрахунком вартості |
| `POST` | `/bookings/quote` | client | Розрахувати вартість без бронювання |
| `GET` | `/bookings/{id}` | client | Інформація про бронювання |
| `POST` | `/bookings/{id}/cancel` | client | Скасувати бронювання |
| `GET` | `/bookings` | admin | Список бронювань (фільтри, пагінація) |

### Звіти (admin)

Усі звіти приймають період `?from=01.09.2024&to=30.09.2024` (до 366 днів).

| Шлях | На яке питання відповідає |
|---|---|
| `/reports/summary` | Скільки заробили (оренда / послуги), скільки бронювань, яка частка скасувань, середній чек? |
| `/reports/rooms` | Які зали приносять найбільше грошей, а які простоюють (завантаженість у %)? |
| `/reports/services` | Які послуги замовляють найчастіше і скільки вони приносять? |
| `/reports/tariffs` | Скільки виручки дають ранкові, стандартні, пікові та вечірні години? |
| `/reports/hourly-demand` | У які години зали найзавантаженіші? |

Повна документація з усіма полями й прикладами доступна у Swagger: `/api-docs`.

## Приклади

**Пошук залів** (приклад із ТЗ: 01.09.2024, 10:00–14:00, 50 осіб):

```bash
curl -H "X-API-Key: <CLIENT_API_KEY>" "http://localhost:3000/api/v1/rooms/available?date=01.09.2024&startTime=10:00&endTime=14:00&capacity=50"
```

У відповіді будуть Зал A та Зал B (Зал C вміщує лише 30 осіб), і для кожного розраховано `estimatedRentPrice`.

**Бронювання:**

```bash
curl -X POST http://localhost:3000/api/v1/bookings \
  -H "X-API-Key: <CLIENT_API_KEY>" -H "Content-Type: application/json" \
  -d '{"roomId":"<id Залу A>","date":"01.09.2026","startTime":"10:00","durationHours":4,"services":["Проєктор","Wi-Fi"],"customerName":"ТОВ Ромашка"}'
```

```json
{
  "message": "Бронювання підтверджено. Загальна вартість: 9400 грн",
  "data": {
    "id": "65813609-ae9b-4516-897c-f03a622415c4",
    "status": "confirmed",
    "room": { "id": "…", "name": "Зал A" },
    "date": "01.09.2026",
    "startTime": "10:00",
    "endTime": "14:00",
    "durationHours": 4,
    "services": [{ "name": "Проєктор", "price": 500 }, { "name": "Wi-Fi", "price": 300 }],
    "price": {
      "currency": "UAH",
      "rent": 8600,
      "services": 800,
      "total": 9400,
      "rentBreakdown": [
        { "tariff": "STANDARD", "from": "10:00", "to": "12:00", "hours": 2, "multiplier": 1, "amount": 4000 },
        { "tariff": "PEAK", "from": "12:00", "to": "14:00", "hours": 2, "multiplier": 1.15, "amount": 4600 }
      ]
    }
  }
}
```

**Формат помилок** однаковий для всіх ендпоінтів:

```json
{ "error": { "code": "CONFLICT", "message": "\"Зал A\" вже заброньовано на цей час. Оберіть інший час або зал" } }
```

| HTTP | code | Коли |
|---|---|---|
| 400 | `VALIDATION_ERROR` | неправильний формат даних (`details` показує, яке поле і що не так) |
| 401 | `UNAUTHORIZED` | немає ключа або ключ недійсний |
| 403 | `FORBIDDEN` | дія доступна лише адміністратору |
| 404 | `NOT_FOUND` | зал / бронювання не знайдено |
| 409 | `CONFLICT` | час зайнятий, назва залу зайнята, бронювання вже скасоване |
| 422 | `BUSINESS_RULE_VIOLATION` | бронювання в минулому, поза робочим часом, недоступна послуга |
| 429 | `TOO_MANY_REQUESTS` | перевищено ліміт запитів |

## Розрахунок вартості

**Вартість = оренда залу за тарифами + ціни обраних послуг.**

| Години | Тариф | Коефіцієнт |
|---|---|---|
| 06:00–09:00 | Ранкові | ×0.90 (знижка 10%) |
| 09:00–12:00 | Стандартні | ×1.00 |
| 12:00–14:00 | Пікові | ×1.15 (націнка 15%) |
| 14:00–18:00 | Стандартні | ×1.00 |
| 18:00–23:00 | Вечірні | ×0.80 (знижка 20%) |

Бронювання, що зачіпає кілька тарифів, ділиться на частини, і кожна частина рахується за своїм коефіцієнтом.
Приклад: Зал A (2000 грн/год), 10:00–14:00 = 2 год × 2000 + 2 год × 2000 × 1.15 = **8600 грн**.

Тарифна сітка задана як дані в одному файлі: [src/modules/pricing/tariffs.js](src/modules/pricing/tariffs.js). Щоб змінити знижку чи додати тариф, достатньо змінити цей файл.

## Структура проєкту

```
src/
├── server.js                 # точка входу: конфігурація, БД, запуск, коректна зупинка
├── app.js                    # Express-застосунок: middleware безпеки, Swagger, маршрути
├── config/                   # читання й перевірка змінних оточення
├── db/                       # з'єднання, міграції (SQL), початкові дані
├── middlewares/              # автентифікація, валідація, rate limit, обробка помилок
├── shared/                   # помилки, гроші, дати, логер, спільні схеми валідації
├── docs/openapi.yaml         # специфікація Swagger / OpenAPI
└── modules/
    ├── index.js              # складання залежностей (Dependency Injection)
    ├── pricing/              # тарифи, розрахунок вартості, перевірка часу (чиста логіка)
    ├── rooms/                # зали та послуги
    ├── bookings/             # бронювання
    └── reports/              # звіти
tests/                        # юніт-тести розрахунку та інтеграційні тести API
```

Кожен модуль поділено на однакові шари:

```
routes → controller → service → repository → БД
          (HTTP)     (бізнес-правила) (SQL)
```

- **schemas**: перевірка вхідних даних (Zod)
- **presenter**: формат відповіді (копійки → гривні, хвилини → «10:00»)

## Тести

```bash
npm test
```

49 тестів перевіряють:
- **розрахунок вартості** в усіх тарифах, на межах тарифів і для пів години;
- **API залів**: створення, редагування, видалення, пошук, валідацію, права доступу;
- **API бронювань**: подвійне бронювання, бронювання впритул, бронювання в минулому, недоступні послуги, скасування, фіксацію ціни;
- **звіти**: кожен звіт на заздалегідь відомих даних;
- **безпеку**: 401 без ключа, rate limit, некоректний JSON, спробу SQL-ін'єкції, безпечні заголовки.

Тести працюють з базою в пам'яті і з зафіксованим «поточним часом», тому результат не залежить від дати запуску.
